## Three things that were not what the schema said

`matches.winner`, `matches.target_runs` and `matches.result_method` are **NULL
for every row on Supabase**. `replay_log.py` mirrors only the columns the
serving path reads. The hero caption was built on two of them, and asking
Supabase returned a confident `null` rather than an error.

That is the third instance of this shape, after `players.batting_hand` (0 of
18,468) and `teams.short_name` (0 of 350). All three are in a sync tuple, which
is what makes them look populated. **A mirrored column is empty until something
is shown to write it** — treated as the default expectation now, and written
into `scripts/corpus.mjs`, which is where the identity is read from instead.

Batting order is not in `matches` at all: `team_a` and `team_b` are the two
sides, not an order. It comes from `deliveries.batting_team_id`, which is empty
on Supabase too — so the hero fixture is generated against local Postgres and
committed, and the header's live slot labels its two sides in table order and
does not claim which is batting.

## The landing page fell back on its first real build, and said so

The page rendered its committed counts with the "not answering right now" note
while both queries succeeded when run by hand a minute later. The first version
of the fallback was silent, so this looked like a mystery rather than an event.

Adding one `console.warn` on the failure path only — standing rule 14 — named
it on the very next build:

```
[landing] matches: using the committed count from 2026-09-23 - query failed: JWT issued at future
```

The local clock leads Supabase by about **2.1 seconds**, measured against the
`Date` header on the project URL. That is enough to make `iat` validation
intermittent, which matches the observed pattern exactly: one build fails, the
next succeeds, standalone probes pass. It is not a paused project, and without
the log line it would have been attributed to one.

The second version of that logging printed `query failed: ` with nothing after
it, because a Supabase error is not always an `Error` and does not always carry
`.message`. A line that proves something broke and says nothing about what is
the line rule 14 is against, so `describe()` now tries `message`, `code`,
`details` and `hint` before serialising.

## The hero was invisible without JavaScript

The draw animation (§1.7) was first written as state: the clip starts at width
0 and opens on mount. That put `width="0"` into the server-rendered HTML, so
the hero — the one element the page is built around, and the one chosen
specifically because it must never fail to render — was blank until hydration
and blank forever without JavaScript.

Moved to a CSS keyframe scaling the clip from zero. The HTML now contains the
finished strip, the animation is decoration on top, and
`prefers-reduced-motion` is a media query rather than a branch. It also deleted
a `useState` and a `useEffect`.

**The general shape: an entrance animation implemented as state makes the
pre-animation state the rendered state.** Anything that must survive without
JavaScript has to animate from a complete DOM, not into one.

## Decisions

| Decision | Why |
|---|---|
| ISR at one hour, not `force-dynamic` | Free-tier pauses have run to 3.3 h in this project. The front door must not be a 500 for that window. |
| Nav carries Ask and Accuracy only | `/matches` and `/players` are sessions 3 and 4. A nav item that 404s is a gap hidden behind something that looks functional. |
| Deliveries figure is a committed constant | `deliveries` is empty on Supabase by design and denied to anon. The page states where it was counted. |
| Matches figure comes from the calibration report | `/accuracy` reads the same row, so the two pages cannot disagree about how much evidence exists. Also sidesteps PostgREST having no `count(DISTINCT)`. |
| Live slot keys off prediction recency | `matches.status` is never updated — nothing in the repo runs `UPDATE matches` — so the September 2026 rows are still `'live'` and always will be. |

## Open, carried forward

1. **`matches.status` is write-once.** Nothing updates it. It will mislead
   `/matches` in session 3 exactly as it would have misled the header here.
   Worth fixing in the worker rather than routed around a second time.
2. **The local clock leads Supabase by ~2s.** Intermittent build-time query
   failures will continue until it is synced. The page degrades correctly, so
   this is a nuisance rather than a fault.
3. **A build with no Supabase environment fails** at `app/api/agent/route.ts`,
   which validates env at module scope. Pre-existing, unrelated to this
   session, and not a real deployment scenario — but it means "build with no
   env" cannot be used as a test. Building against an unreachable database
   works and is the case that matters.
4. **The live slot renders a single mark**, because one prediction has no
   history to draw. It should carry the innings so far once `/matches` exists
   and there is a loader for it.
5. **`teams.short_name` is still NULL for 350 rows.** Abbreviations are derived
   from the name. A curated mapping would be better and is 350 rows of work.
